프롬프트를 잘 쓰는 요령은 하나뿐입니다 — **에이전트가 뭘 모르는지 채워주는 것.**
에이전트는 당신 머릿속과 화면을 못 봅니다. 에러 메시지, 하려던 것, 지금까지 한 것을 주면 대부분 풀립니다.

## 시작할 때

**뭘 만들지 정하기**
```
나는 개발이 처음이야. [만들고 싶은 것 한 줄]을 만들어보려고 해.

바로 코드를 짜지 말고, AskUserQuestion 도구로 나를 먼저 인터뷰해줘.
무엇을 만들지, 누가 쓸지, 꼭 필요한 기능과 굳이 필요 없는 기능,
그리고 내가 미처 생각 못한 부분을 물어봐줘.
선택지를 줄 때는 각각이 뭘 의미하는지 쉽게 설명해줘.

인터뷰가 끝나면 sandbox/<내이름>/SPEC.md 에 스펙을 정리해줘.
그 다음 어떤 순서로 만들면 될지 계획도 알려줘. 아직 구현은 하지 마.
```

**너무 큰 걸 고른 것 같을 때**
```
지금 계획이 하루 안에 끝낼 수 있는 크기인지 솔직하게 봐줘.
크다면, 오늘 안에 "동작하는 뭔가"를 완성할 수 있게 범위를 줄여줘.
뺀 기능은 나중에 할 수 있게 SPEC.md 아래에 적어두고.
```

## 만들 때

**한 단계씩 시키기**
```
SPEC.md의 계획 중 1단계만 구현해줘. 다 만들지 말고 1단계만.
구현한 다음에는 내가 직접 실행해서 확인할 수 있게 실행 방법을 알려줘.
```

**결과를 이해하고 넘어가기**
```
방금 만든 코드가 무슨 일을 하는지 한 줄씩 설명해줘.
전문용어가 나오면 그게 뭔지도 같이 풀어서 설명해줘.
```

**커밋하기**
```
방금 확인했어, 잘 동작해. 이 변경사항을 커밋해줘.
커밋 메시지는 우리 규칙(feat:, fix: 같은 형식)에 맞춰줘.
```

## 막혔을 때

**에러가 났을 때**
```
이런 에러가 났어: [에러 전체 붙여넣기]
왜 이런 일이 생겼는지 먼저 한국어로 설명해주고, 그 다음에 고쳐줘.
```

**뭘 물어봐야 할지도 모르겠을 때**
```
지금 [무엇]을 하려는데 어디서부터 손대야 할지 모르겠어.
지금 상황: [아는 만큼만 적기]
나한테 필요한 질문을 네가 먼저 해줘. 그걸 답하면서 정리해보고 싶어.
```

**에이전트가 자꾸 엉뚱한 걸 만들 때**
```
잠깐, 내가 원한 건 이게 아니야. 내가 원한 건 [무엇]이야.
지금 만든 것과 뭐가 다른지 짚어주고, 내 설명 중 어디가 애매했는지 알려줘.
다음부터 어떻게 말하면 정확히 전달될지도 같이 알려줘.
```

## Git

**한 단계씩 안내받기**
```
이제 Git을 쓸 차례야. 나는 Git이 처음이니까 한 번에 한 단계씩,
각 명령이 무슨 뜻인지 한 줄씩 설명하면서 알려줘.
내가 명령을 실행하면 결과를 붙여넣을 테니 다음 단계를 알려줘.

목표: [하려는 것]
```

**충돌이 났을 때**
```
push하려니까 이런 메시지가 나왔어: [메시지 전체 붙여넣기]

나는 merge conflict가 처음이야. 지금 무슨 상황인지 그림 그리듯이 먼저 설명해줘.
그 다음에 어떤 선택지가 있는지 알려주고, 한 단계씩 같이 해결하자.
파일을 마음대로 고치지 말고, 어느 쪽 내용을 남길지는 나한테 물어봐줘.
```

**뭔가 잘못한 것 같을 때**
```
Git에서 실수한 것 같아. 지금 상황은 이래: [git status 결과 붙여넣기]
내가 하려던 건 [무엇]이야.
지금 상태를 먼저 설명해주고, 되돌리는 방법을 한 단계씩 알려줘.
파일을 잃어버리지 않는 안전한 방법으로 부탁해.
```

## PR과 리뷰

**PR 올리기**
```
이제 작업이 끝났어. PR을 올리고 싶어.
PR 템플릿(.github/PULL_REQUEST_TEMPLATE.md)의 항목을 채울 수 있게
나한테 하나씩 물어봐줘. 특히 "왜 이렇게 했나요"랑
"에이전트와 일하며 배운 것"은 내 말로 쓰고 싶으니까 초안만 잡아줘.
```

**리뷰 결과 판단하기**
```
방금 리뷰 결과에서 이 지적이 무슨 뜻인지 설명해줘: [붙여넣기]
이게 이 PR에서 실제로 문제가 될 만한 건지, 아니면 사소한 건지 판단을 도와줘.
```

**리뷰를 받고 반영하기**
```
내 PR에 이런 리뷰 코멘트가 달렸어: [붙여넣기]
이 지적이 타당한지 먼저 같이 판단해줘. 타당하면 고치고,
동의하지 않는다면 내가 왜 그렇게 했는지 설명하는 답글 초안을 잡아줘.
```

## 하네스 만들기 (Day 3)

**CLAUDE.md 규칙 추가**
```
CLAUDE.md에 규칙을 추가하고 싶어. 문제는 이거야: [반복된 실수].
이걸 막을 규칙을 한 줄로 제안해줘. 단, 짧고 구체적이어야 해.
CLAUDE.md는 매 세션 읽히는 고정 비용이라, 길어지면 오히려 무시되니까
"이 줄이 없으면 에이전트가 실수할까?"를 기준으로 판단해줘.
```

**스킬 만들기**
```
`.claude/skills/` 에 팀 공용 스킬을 하나 만들고 싶어.
주제는 [무엇]이야. 나는 이 작업을 이런 순서로 해왔어:
1. [...] 2. [...] 3. [...]

이걸 스킬 파일로 만들어줘. 다른 팀원이 이 스킬을 불렀을 때
나만큼 잘 할 수 있게, 애매한 부분은 나한테 물어보면서 채워줘.
```

**서브에이전트 써보기**
```
서브에이전트를 하나 써서 우리 레포의 sandbox/ 폴더 전체를 훑고,
각 사람이 뭘 만들었는지 한 줄씩 요약해줘.
파일 내용을 전부 이 대화에 가져오지는 말고 요약만 보고해줘.
```

## 알아두면 좋은 것

- **길게 쓰는 걸 두려워하지 마세요.** 짧고 애매한 지시가 제일 나쁩니다.
- **에러는 잘라내지 말고 통째로** 붙여넣으세요. 마지막 줄만 주면 원인을 놓칩니다.
- **"모르겠어"라고 말해도 됩니다.** 어디까지 이해했는지 알려주면 거기서부터 설명해줍니다.
- **대화가 길어져 헤매기 시작하면** `/clear`로 새로 시작하세요. 중요한 건 이미 파일에 저장돼 있습니다.

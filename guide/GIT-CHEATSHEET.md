# Git 치트시트 (개발 처음인 사람용)

외우려 하지 마세요. **막힐 때마다 여기 와서 찾아보면 됩니다.** 3일 지나면 손이 기억합니다.

---

## 먼저: Git이 대체 뭔가요

Git은 **"저장 지점을 남기며 작업하는 도구"**입니다. 게임 세이브 파일이라고 생각하면 됩니다.

여러 명이 같이 일할 때 진가가 나옵니다. 각자 **자기 세이브 파일(브랜치)**에서 따로 작업하다가,
나중에 하나로 합칩니다(머지). 그래서 서로의 작업을 덮어쓸 일이 없습니다.

| 단어 | 진짜 뜻 |
|---|---|
| **clone** | GitHub에 있는 폴더를 내 컴퓨터로 통째로 복사 |
| **branch** | 내 전용 작업 공간을 하나 따로 만드는 것 |
| **commit** | 지금까지 한 작업을 "저장"하는 것 (메모를 붙여서) |
| **push** | 내 컴퓨터의 저장 내용을 GitHub에 올리는 것 |
| **PR** (Pull Request) | "내 작업을 팀 코드에 합쳐주세요"라는 요청서 |
| **merge** | 그 요청이 승인돼서 실제로 합쳐지는 것 |
| **conflict** | 두 사람이 같은 줄을 다르게 고쳐서, 컴퓨터가 어느 쪽이 맞는지 못 정하는 상태 |

---

## 하루를 시작할 때

```bash
git checkout main          # 공용 작업 공간으로 이동
git pull                   # 남들이 올린 최신 내용 받아오기
```

> 이걸 안 하면 옛날 코드 위에서 작업하게 되어 나중에 충돌이 커집니다. **매일 아침 습관으로.**

---

## 새 작업을 시작할 때

```bash
git checkout -b sandbox/내이름-주제      # 내 작업 공간 만들고 그리로 이동
```

예: `git checkout -b sandbox/jimin-todo-cli`

---

## 작업하다가 저장할 때

```bash
git status                 # 지금 뭐가 바뀌었는지 확인 (자주 보세요)
git add .                  # 바뀐 것들을 저장 대상에 올리기
git commit -m "feat: 할 일 추가 기능 구현"
```

커밋 메시지 앞에 붙이는 말:

| 접두사 | 언제 |
|---|---|
| `feat:` | 새 기능을 만들었을 때 |
| `fix:` | 잘못된 걸 고쳤을 때 |
| `docs:` | 문서만 고쳤을 때 |
| `chore:` | 설정·정리 등 그 외 |

---

## GitHub에 올릴 때

```bash
git push -u origin sandbox/내이름-주제     # 첫 push (브랜치를 새로 올림)
git push                                  # 두 번째부터는 이걸로 충분
```

push하면 터미널에 PR을 만들 수 있는 링크가 뜹니다. 그걸 누르면 됩니다.

---

## 남의 PR을 리뷰할 때

```bash
gh pr checkout 12          # 12번 PR을 내 컴퓨터로 가져오기
```

그 다음 Claude Code에서 `/code-review 12`

## 충돌(conflict)이 났을 때

**당황하지 마세요. 아무것도 망가지지 않았습니다.** 컴퓨터가 "어느 쪽을 남길지 네가 정해줘"라고 묻는 것뿐입니다.

먼저 상황을 봅니다.

```bash
git status                 # 어떤 파일이 충돌했는지 알려줌
```

충돌한 파일을 열면 이렇게 생겼습니다.

```
<<<<<<< HEAD
내가 쓴 내용
=======
상대가 쓴 내용
>>>>>>> main
```

`<<<<<<<`, `=======`, `>>>>>>>` 세 줄을 **지우고**, 남길 내용만 남기면 끝입니다.
양쪽 다 남겨야 할 때도 많습니다.

그 다음:

```bash
git add .
git commit                 # 충돌 해결 완료
git push
```

> 어느 쪽을 남길지 애매하면 **혼자 정하지 말고 상대에게 물어보세요.** 그게 정답 동작입니다.

---

## 뭔가 잘못한 것 같을 때

**거의 모든 실수는 되돌릴 수 있습니다.** 혼자 해결하려다 더 꼬이게 만들지 말고 물어보세요.

```
Git에서 실수한 것 같아. 지금 상황은 이래: [git status 결과 붙여넣기]
내가 하려던 건 [무엇]이야.
지금 상태를 먼저 설명해주고, 되돌리는 방법을 한 단계씩 알려줘.
파일을 잃어버리지 않는 안전한 방법으로 부탁해.
```

**절대 혼자 실행하지 말아야 할 명령**: `git reset --hard`, `git push --force`
(되돌릴 수 없게 만들 수 있습니다. 가이드에게 먼저 물어보세요.)

## 만능 탈출 프롬프트

정말 모르겠을 때 이걸 그대로 붙여넣으세요.

```
Git 상태가 어떻게 된 건지 모르겠어.
아래는 내 상황이야:

$ git status
[결과 붙여넣기]

$ git log --oneline -5
[결과 붙여넣기]

내가 원하는 건 [무엇]이야.
지금 무슨 상태인지 쉬운 말로 설명해주고, 다음에 뭘 해야 할지 한 단계씩 알려줘.
```

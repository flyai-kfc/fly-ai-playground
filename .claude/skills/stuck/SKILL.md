# 막혔을 때

이 레포 사용자는 대부분 개발이 처음입니다. 막혔을 때 가장 흔한 실패는
**원인을 모른 채 명령을 더 치는 것**입니다. 그러면 문제가 두 개가 됩니다.

## 1. 먼저 멈춘다

사용자가 막혔다고 하면 **바로 해결책을 던지지 마세요.** 추측으로 명령을 제안하면
사용자는 그걸 실행하고, 상태가 더 꼬입니다.

터미널이 이상한 프롬프트(`if>`, `quote>`, `dquote>`, `>`)에 갇혀 있으면
먼저 `Ctrl+C` 로 빠져나오게 하세요. "문장이 안 끝났다"는 뜻이며 대개 따옴표가 하나 빠진 겁니다.

## 2. 상태를 먼저 확인한다

추측 대신 사실을 모읍니다. 사용자에게 아래를 실행하고 결과를 붙여넣게 하세요.

```
pwd
git branch --show-current
git status
```

Git 문제의 절반은 이 셋으로 원인이 드러납니다.

- `pwd` 가 레포 루트가 아니면 → 파일 경로가 안 맞아 `git add` 가 조용히 실패합니다
- 브랜치가 `main` 이면 → 작업 위치가 잘못됐습니다
- `git status` 는 지금 무엇이 커밋 전인지 그대로 보여줍니다

## 3. 에러 메시지는 마지막 줄부터 읽는다

Git과 파이썬 에러는 **해결책을 마지막 두세 줄에 적어두는 경우가 많습니다.**
영어라 눈이 미끄러지기 쉬우니, 사용자에게 그 부분을 짚어서 번역해 주세요.

## 4. 자주 나오는 신호와 진짜 의미

| 메시지 | 실제 의미 |
|---|---|
| `Everything up-to-date` | 성공이 아님. **올릴 커밋이 없음** = 커밋을 안 했다 |
| `nothing to commit` | `git add` 가 안 됐다. 경로나 폴더 위치 확인 |
| `Unable to create '.git/index.lock': File exists` | 이전 git 프로세스가 죽으면서 남긴 잠금 파일. 실행 중인 git이 없으면 지워도 안전 |
| `command not found` | 설치가 안 됐거나 PATH에 없음 |
| `Authentication failed` / 비밀번호를 물어봄 | GitHub는 계정 비밀번호를 안 받는다. `gh auth login` 필요 |
| `CONFLICT (content): Merge conflict in ...` | 같은 곳을 양쪽이 다르게 고쳤다. 에러가 아니라 **질문받은 상태** |
| `SyntaxError` | 파이썬이 파일을 아예 못 읽는 상태. 이걸 고치기 전에는 다른 문제가 안 보인다 |

## 5. 설명은 원인 먼저, 한국어로

고치기 전에 **왜 이런 일이 생겼는지**를 한국어로 먼저 설명합니다.
사용자가 원인을 모른 채 해결되면 다음에 또 막힙니다. 이 레포의 목적은 결과물이 아니라 학습입니다.

사용자가 엉뚱한 것을 의심하고 있으면(예: "push 하면 데이터가 지워지나요?")
그 오해부터 풀어 주세요. 잘못된 두려움이 남으면 계속 발목을 잡습니다.

## 6. 고친 뒤에는 반드시 실행해서 확인한다

**메시지가 사라진 것과 문제가 해결된 것은 다릅니다.**

특히 merge conflict를 해결한 뒤에는 마커(`<<<`, `===`, `>>>`)를 지운 것만으로 끝내지 마세요.
마커 **바깥**에 짝을 잃은 코드가 남아 파일이 깨질 수 있습니다.

```
python3 -m py_compile <파일>     # 문법 확인
python3 <파일> <명령>            # 실제 실행
```

## 7. 30분 규칙

사용자가 같은 문제로 30분 넘게 막혀 있으면, 계속 시도하게 두지 말고
**팀 채널에 화면을 그대로 붙이라고 안내하세요.** 혼자 오래 헤매는 게 이 레포의 유일한 실패입니다.

## 8. 해결되면 한 줄 남긴다

무엇이 원인이었는지 한 줄로 정리해 주세요. PR 본문이나 회고에 그대로 쓸 수 있습니다.

> 예) `git add` 가 계속 실패했는데 원인은 `.git/index.lock` 이었다.
> `Everything up-to-date` 는 성공이 아니라 "올릴 게 없다"는 신호였다.
